**Renderer gap worth fixing rather than repeating by hand:** `render-vault.sh` is create-only
for notes *and* patch-only-within-render-set for reverse lookups. A newly added workflow
therefore lands with a complete "Depends on" section while every note it points at stays
silently stale. Adding a workflow should trigger a reverse-lookup patch on every resource and
callee it references, regardless of whether those notes are being rendered.

No trigger note was created this run — `schedule-every-4-hour-s` already existed (four other
workflows use a 4-hour schedule) and only needed the new usage appended. The renderer reported
`exists, skipping`, which is correct behaviour for the note but is exactly the case where the
reverse-lookup patch is missed.

**Why:** the enrolment URL was not clickable. In plain text there is no anchor markup, so

never linkifies anything, so a draft could not verify it either way (the `mailto:` address in
the same body was equally unlinked). An explicit `<a href>` removes the guesswork.

**Why it was cheap:** the two senders are interface-identical — same 11 inputs and types, same
returned status vocabulary, same `is_pe_inbox` rule, same fail-safe `x == null ? true : x`
defaults on `create_draft` and `skip_email`. Verified node-by-node before swapping. Reverting
is a one-line `workflowId` change plus restoring the plain-text body block.
